## 1. 目的与读者

这份说明书解释两件事：原型为什么长这样，以及每个界面在授权语义上如何工作。

- **产品与需求评审者**：核对界面是否覆盖 PROJECT_SPEC_V2 的授权需求，以及交互是否符合预期。
- **前端实现者**：把原型中的布局、状态与权限映射当作实现基准。
- **后端实现者**：从控件级权限映射中确认每个界面动作对应哪个权限码。

原型不连接真实后端，所有数据为示意内容，所有写操作只给出提示反馈。

---

## 2. 设计命题

RBAC 产品最常见的问题是「权限不可见」：管理员只能靠记忆或翻数据库知道谁能做什么，普通用户则只看到一堆消失的按钮，不知道是坏了还是没权限。

因此这套界面的核心不是「把系统管理页面画好看」，而是回答三个问题：

1. **当前身份被允许做什么？** —— 用一个可切换的身份和一张权限台账直接回答。
2. **为什么这个按钮不见了？** —— 用「可见 / 隐藏操作计数」和「仅查看」占位解释，而不是无声消失。
3. **两个角色的边界差在哪？** —— 用角色 × 模块 × 操作的矩阵一次看完。

**不做什么**：不重画 Agent / 模型 / 知识库等业务页面；不模拟真实数据流；不引入前端框架或构建工具。

## 3. 设计方向：通行证台账（Access Ledger）

### 3.1 概念

把 RBAC 当作一栋需要通行证的楼：角色是通行证，权限码是门禁点位，授权矩阵是台账。界面的任务是把「谁、能进哪扇门」写清楚、对得上、随时可查。

### 3.2 视觉语言

- **墨蓝侧栏 + 冷纸内容区**：深色导航承担「建筑结构」，浅色内容区承担「台账纸面」，两者对比明确但不刺眼。
- **钴蓝只给主操作与「已授予」**：颜色承担语义。绿色只表示超级管理员的内置授权，赭黄只表示待处理，灰色表示未授予或停用。
- **等宽字只给权限码**：`agent:publish` 这类编码需要逐字核对，等宽是功能选择，不是装饰。
- **克制的结构线**：用 1px 分隔线组织表格与分组，不用阴影堆叠卡片；页面内只有一个真正的「大数字区」（指标条），且数字用窄体 Bahnschrift，避免模板感。
- **动效只响应操作**：身份切换、抽屉开合、提示出现。没有入场动画，没有滚动特效。

### 3.3 与原项目的关系

沿用现有产品的信息架构（左侧导航、系统管理子菜单、面包屑、表格 + 分页 + 弹窗的操作习惯），保证原型不是另一套产品。差异在于：提高了信息密度、统一了权限语义色、增加了身份切换与权限台账这两个授权专用组件。

### 3.4 刻意避开的方向

- 不做三张同款渐变数据卡 + 图标圆底的仪表盘模板。
- 不用奶油色背景 + 衬线大标题 + 陶土色的通用审美组合。
- 不堆叠入场动画与卡片悬浮效果。
- 不用「01 / 02 / 03」给非序列内容编号。

## 4. 设计令牌

### 4.1 颜色

| 令牌 | 色值 | 用途 |
|---|---|---|
| `--ink` | `#16233B` | 侧边栏、深色面板、主文字 |
| `--ink-2` | `#1D2C46` | 深色面板次级底色 |
| `--paper` | `#F4F6FA` | 内容区背景 |
| `--surface` | `#FFFFFF` | 面板、表格、抽屉 |
| `--cobalt` | `#2F4DE0` | 主按钮、激活态、角色授予的权限点 |
| `--cobalt-600` | `#2740C4` | 主按钮悬停 |
| `--cobalt-soft` | `#EDF0FE` | 主色浅底（徽章、专项计数） |
| `--verdant` | `#1F7A5C` | 超级管理员内置授权、健康状态 |
| `--amber` | `#A9640A` | 待分配、待处理 |
| `--danger` | `#B3382C` | 删除等破坏性操作 |
| `--slate` | `#5B6B84` | 次级文字 |
| `--slate-2` | `#8492A6` | 辅助说明、占位 |
| `--line` | `#E1E6EF` | 分隔线、表格边 |
| `--line-strong` | `#CBD4E2` | 输入框、描边按钮 |

语义约定：

- 绿色 = 内置/绕过（超级管理员），不用于普通「成功」提示，避免与授权语义混淆。
- 蓝色 = 角色明确授予。
- 空心圆 = 未授予。**不使用红色表示未授予**，红色只留给破坏性动作。

### 4.2 字体与字阶

| 角色 | 字体栈 | 说明 |
|---|---|---|
| 界面文字 | `Microsoft YaHei` / `PingFang SC` / `Segoe UI` / system-ui | 中文正文，14px / 1.6 |
| 数字与拉丁 | `Bahnschrift` / `DIN Alternate` / `Segoe UI` | 指标数字、编号、表格数字，窄体更整齐 |
| 权限码 | `JetBrains Mono` / `Cascadia Mono` / Consolas | 等宽，保证逐字核对 |

字阶：

| 用途 | 字号 | 字重 | 行高 |
|---|---|---|---|
| 页面标题 H1 | 25px | 700 | 1.3 |
| 索引页主张 | 42px | 700 | 1.28 |
| 面板标题 | 14px | 600 | 1.5 |
| 正文 / 表格 | 13–14px | 400 | 1.6 |
| 辅助说明 | 12–12.5px | 400 | 1.6 |
| 指标数字 | 26px | 600 | 1.2 |
| 权限码 | 11.5px | 400 | 1.7 |

行宽控制在 44–62 个中文字符以内；长说明使用 `max-width` 限制，不铺满整个屏幕。

### 4.3 间距、圆角、描边、阴影

| 令牌 | 值 | 用途 |
|---|---|---|
| 页面内边距 | 26px 28px 48px | 内容区 |
| 面板内边距 | 14–18px | 面板头 / 主体 |
| 表格单元格 | 12px 16px（权限目录 9px 16px） | 行高与密度 |
| 间距阶梯 | 4 / 8 / 10 / 14 / 18 / 26 / 34 | 组件与区块 |
| 圆角 | 面板 12px，抽屉 0（侧贴边），按钮 8px，徽章 999px | 层级越高、圆角越大 |
| 描边 | 1px `--line`；输入框 1px `--line-strong` | 唯一的结构装饰 |
| 阴影 | 仅抽屉使用 `-18px 0 40px rgba(22,35,59,.12)` | 面板不加阴影 |

### 4.4 图标

线性图标，24×24 视图框，1.7px 描边，`currentColor`。行内操作图标在行内上下文中加粗到 2px，保证小尺寸可辨。图标通过 `data-icon` 属性在运行时注入，避免在 HTML 中重复 SVG。

### 5.2 权限模型在界面上的三种呈现

| 呈现 | 位置 | 回答的问题 |

| 身份切换器 | 顶栏右侧 | 我现在是谁 |

| 操作计数 + 按钮显隐 | 每个列表页 | 这一页我能做什么、少了什么 |

## 6. 页面设计

### 6.0 全局骨架

所有后台页面共享同一骨架，只在内容区变化。

```
┌──────────────┬──────────────────────────────────────────────────┐
│ 辰光 Agent    │ 首页 / 系统管理 / 用户管理      演示身份 [管理员|运营|审计] │
│ Enterprise   ├──────────────────────────────────────────────────┤
│              │                                                  │
│ 平台功能      │  页面标题                                        │
│  工作台       │  页面说明                                        │
│  Agent管理    │  ┌ 当前身份 · N 项操作可用 · M 项因权限隐藏 ─────┐   │
│  模型管理     │  └──────────────────────────────────────────────┘   │
│  Prompt管理   │  ┌ 指标 ┬ 指标 ┬ 指标 ┬ 指标 ┐                    │
│  知识库       │  └──────┴──────┴──────┴──────┘                    │
│  工具管理     │  ┌ 工具栏：搜索 / 筛选 ─────────────────────────┐   │
│  对话日志     │  │ 表格                                           │   │
│  数据统计     │  │ 行 · 行 · 行                                   │   │
│              │  └ 分页 ────────────────────────────────────────┘   │
│ 系统管理      │                                                  │
│  用户管理     │                                                  │
│  ...         │                                                  │
│              │                                                  │
│ 无权限页示例  │                                                  │
│  ┌ 用户 ┐     │                                                  │
└──┴──────┴─────┴──────────────────────────────────────────────────┘
```

顶栏的「演示身份」是三个按钮组成的分段控件，`aria-pressed` 标记当前项。切换后：

1. 重新计算所有 `[data-perm]` 元素的可见性；
2. 更新操作计数；
3. 重绘权限矩阵或摘要；
4. 弹出一次提示：「已切换为平台运营 · 当前可见 33 项权限」。

身份保存在 `localStorage`，跨页面保持一致；也可通过 `?role=admin|ops|auditor` 直接进入指定身份。

### 6.4 用户管理（users.html）

**目标**：演示按钮级授权最直观的场景。

**布局**：页头操作区 → 提示条 → 指标 → 搜索/筛选 + 用户表格 → 分页。提供两个抽屉：添加用户、分配角色。

```
页头：用户管理                                  [+ 添加用户]
提示条：● 当前身份 超级管理员 · 13 项操作可用 · 0 项隐藏
指标：账号总数 128 | 已启用 121 | 内置角色 3 | 待分配角色 4
┌ 搜索用户名、邮箱或角色 ──────────  [全部][已启用][已停用] ┐
│ ID 用户        邮箱              角色      状态   最近登录  操作 │
│ 1  周管理       admin@…          admin     已启用  今天     🔒 │
│ 2  陈运营       chen.ops@…       ops       已启用  今天     ✎ 🛡 🗑 │
│ 3  李审计       li.audit@…       auditor   已启用  昨天     ✎ 🛡 🗑 │
│ …                                                          │
└ 共 128 条，当前显示 1–5                     [分页]        ┘
```

**权限行为**：

| 控件 | 权限码 | 无权限时 |
|---|---|---|
| 编辑用户 | `user:update` | 隐藏 |
| 添加用户 | `user:create` | 隐藏 |
| 行内分配角色 | `user:assign_role` | 隐藏 |
| 行内删除 | `user:delete` | 隐藏 |
| 内置账号 admin | — | 锁图标占位，不可操作 |

只读审计身份下，操作列全部为空时会显示「仅查看」，避免让人误以为加载失败。对比截图见 `images/users-readonly.png`。

**抽屉**：

- 添加用户：用户名、邮箱、初始密码、初始角色（可多选）。
- 分配角色：目标用户摘要 + 角色复选；`admin` 角色禁用并注明「内置角色，不可通过界面分配」。

### 6.5 角色管理（roles.html）

**目标**：管理角色本身，并解释「权限如何生效」。

**布局**：页头 + 指标条 + 左表格、右说明栏（权限如何生效 / 角色约束）。抽屉：创建或编辑角色、分配权限。

```
页头：角色管理                                  [+ 创建角色]
指标：角色总数 3 | 已授权用户 18 | 内置角色 1 | 本周变更 6
┌────────────────────────────────┬─────────────────────┐
│ 编码     名称      类型 权限数 用户数 操作 │ 权限如何生效         │
│ admin   超级管理员  内置   69    1    🔒 │ 1. 接口声明权限码…   │
│ ops     平台运营    自定义 33    12   ✎ 🔑 🗑 │ 2. 角色取并集…     │
│ auditor 只读审计    自定义 15    5    ✎ 🔑 🗑 │ 3. 不含则 403…     │
│                                          │ 4. 超管跳过判断      │
│ 共 3 个角色                    [分页]    ├─────────────────────┤
└────────────────────────────────┴ 角色约束（内置保护、删除前置）┘
```

**权限行为**：

| 控件 | 权限码 |
|---|---|
| 创建角色 | `role:create` |
| 编辑角色 | `role:update` |
| 分配权限 | `role:assign_permission` |
| 删除角色 | `role:delete` |

内置 `admin` 行只显示锁图标；其权限不可清空。删除角色前提示需先解除用户关联。

**分配权限抽屉**：按模块分组，左侧名称、右侧权限码，组头显示 `已选 / 总数`；顶部提供筛选输入。抽屉只展示代表性分组，完整清单在权限管理页。

### 6.6 权限管理（permissions.html）

**目标**：把 69 个权限码当作一份可检索的契约来呈现。

**布局**：页头 + 指标 + 工具栏（搜索 + 范围筛选）→ 按模块分组的权限目录 → 分页。

```
页头：权限管理                                  [+ 创建权限]
指标：权限码 69 | 覆盖模块 15 | 角色总数 3 | 本周新增 2
┌ 搜索权限码或名称 ──────── [全部][系统管理][业务模块][用户][Agent][知识库] ┐
│ 用户                                                5 项              │
│   user:read          用户查看                              ✎ 🗑       │
│   user:create        用户创建                              ✎ 🗑       │
│   user:assign_role   用户分配角色                          ✎ 🗑       │
│ 角色                                                5 项              │
│   role:read …                                                       │
└─────────────────────────────────────────────────────────────────────┘
```

**目录结构**（共 15 个模块、69 项）：

| 范围 | 模块 | 数量 |
|---|---|---|
| 系统管理 | 用户 5、角色 5、权限 4、API 密钥 4、审计日志 1、告警规则 4、系统配置 2 | 25 |
| 业务模块 | Agent 8、模型 5、供应商 5、Prompt 6、知识库 11、工具 7、对话日志 1、数据统计 1 | 44 |

**权限行为**：创建权限需要 `permission:create`；行内编辑/删除分别需要 `permission:update` / `permission:delete`。目录行的操作按钮不计入顶部「操作可用」计数，避免数字被 138 个图标淹没。

### 6.7 角色权限矩阵（matrix.html）

**目标**：一屏核对三个角色 × 15 模块 × 5 类操作。本页是为授权评审新增的提案页。

**布局**：页头 → 三张角色摘要卡 → 双行表头矩阵 → 图例 → 读法与边界说明。

```
页头：角色权限矩阵                                [导出] [管理角色]
角色卡：超级管理员 69/69 | 平台运营 33/69 | 只读审计 15/69
┌────────┬──────────── 超级管理员 ────────────┬──────── 平台运营 ───────────┬──────── 只读审计 ─────────┐
│ 模块    │ 查看 创建 编辑 删除 专项 │ 查看 创建 编辑 删除 专项 │ 查看 创建 编辑 删除 专项 │
│ 用户    │  ●   ●   ●   ●   ●    │  ●   ○   ○   ○   ○    │  ●   ○   ○   ○   ○    │
│ Agent   │  ●   ●   ●   ●   ●    │  ●   ●   ●   ○   ●    │  ●   ○   ○   ○   ○    │
│ …       │                       │                       │                       │
└────────┴───────────────────────┴───────────────────────┴───────────────────────┘
● 内置授权  ● 角色授予  ○ 未授予  [3/7] 专项已授予 / 总数
```

**设计要点**：

- 绿色点表示超级管理员的内置授权，蓝色点表示角色明确授予，空心点表示未授予。
- 「专项」列汇总发布、启停、上传、配置等非 CRUD 操作；悬停可看授予比例。
- 模块列与表头在滚动时保持可见。
- 该页为只读视图；「导出」与「管理角色」需要 `role:read`。

### 6.8 无权限（denied.html）

**目标**：把 403 从「一句冷冰冰的拒绝」变成「知道缺什么、下一步做什么」。

**布局**：保留全局侧栏与顶栏，让用户仍有方向感；内容区居中呈现 403、说明、所需权限、三个出口。

```
┌──────────────────────────────────────────────────────┐
│                       403                            │
│            你没有访问这个页面的权限                    │
│   当前身份 只读审计 未被授予 settings:update。          │
│   系统配置涉及密钥与全局参数，只对管理员开放。           │
│                                                      │
│   🔒 所需权限：settings:update | 可联系管理员在角色管理… │
│                                                      │
│   [以超级管理员查看]  [返回工作台]  [查看我的权限]      │
│                                                      │
│   本页为无权限状态的示例。前端路由拦截 + 后端 403。      │
└──────────────────────────────────────────────────────┘
```

**行为**：

- 默认以「只读审计」身份展示，避免出现「超级管理员被拒绝」的语义矛盾。
- 若用户把身份切回超级管理员，页面顶部出现说明：「超级管理员不会遇到此页面，这里仅作状态示例」，同时隐藏「以超级管理员查看」按钮。
- 提供返回工作台与查看权限的路径，不只给一个「返回」按钮。

## 7. 权限交互规范

### 7.1 三层控制

| 层级 | 实现方式 | 无权限表现 |
|---|---|---|
| 菜单 | 导航项 `data-perm` | 不渲染 |
| 路由 | 进入页面前校验（本原型以示例页呈现） | 跳转 403 或工作台 |
| 按钮 | 控件 `data-perm` / `data-perm-any` | 不渲染 |

`data-perm-any="model:read,provider:read"` 表示满足任一即可，对应「模型管理」菜单同时容纳模型与供应商两个入口。

### 7.2 显隐而非禁用

**原则**：没有权限的操作直接隐藏，不显示为禁用状态。禁用的按钮会让人反复尝试并怀疑系统故障；隐藏则表达「这个操作不属于你」。

**例外**：内置账号与内置角色使用锁图标 + `disabled`，因为它们属于「存在但不可操作」的对象，需要让人看见其存在与受保护状态。

### 7.3 用计数解释消失

每个列表页顶部都有提示条：

> ● 当前身份 只读审计 · 0 项操作可用 · 10 项因权限隐藏

这行字解决的是「按钮去哪了」的问题。计数由页面内所有带 `data-perm` 的控件实时统计，不包括权限目录中成百上千的行内图标。

### 7.4 空操作列的处理

当一行内的所有操作按钮都被隐藏时，操作列显示灰色「仅查看」。这不是一个按钮，而是一句状态说明，避免表格出现无法解释的空白。

### 7.5 超级管理员的表达

超级管理员不是「拥有所有权限码」，而是「绕过校验」。界面上用绿色点和「绕过 RBAC」明确区分这两种含义：

- 普通角色：蓝点，逐项授予。
- 超级管理员：绿点，内置、不可逐项编辑。

## 9. 状态与反馈

| 状态 | 处理 |
|---|---|
| 加载中 | 表格显示「加载中…」占位行（原型为静态数据，状态样式已定义） |
| 空数据 | 说明「没有匹配的权限码」，并提示换关键词或切回全部模块 |
| 无权限 | 按钮/菜单隐藏；计数说明原因；页面级进入 403 |
| 写操作成功 | 底部深色提示条，2.6 秒后消失；文案说明实际结果 |
| 高风险操作 | 删除类均带二次确认文案，明确影响范围（原型以提示模拟） |
| 抽屉 | 右侧滑入，遮罩点击或 Esc 关闭；抽屉内首个小控件自动聚焦 |

提示条使用深色底 + 绿色对勾，语气平实，例如「角色已更新，用户权限即时生效」，不使用感叹号或拟人化表达。

## 10. 响应式与可访问性

- **断点**：1080px 以下内容区改单栏、品牌区隐藏；760px 以下侧栏折叠为顶部横向滚动导航，指标条两列。
- **键盘**：所有按钮、链接、输入框保留可见 `:focus-visible` 轮廓；抽屉支持 Esc 关闭。
- **动效**：遵循 `prefers-reduced-motion`，关闭过渡。
- **颜色对比**：正文 `#16233B` 于 `#FFFFFF` 约 13:1；辅助文字 `#5B6B84` 约 5.4:1；蓝点不单独承载信息，矩阵同时提供图例与悬停说明。
- **语义**：当前导航使用 `aria-current`（由 active 样式承担视觉），身份切换使用 `aria-pressed`，抽屉使用 `role="dialog"` 与 `aria-modal`。

## 12. 取舍与后续

### 12.1 本次做出的设计判断

| 判断 | 理由 |
|---|---|
| 权限码总数按 PRD 清单逐条统计为 69 项 | 工具模块 7 项（无独立「导出」），此前文档中「70」为概数；原型以实际清单为准 |
| 新增「角色权限矩阵」页 | 授权评审需要一张能横向比较的视图，属于对 PRD 的补充提案，不改变需求 |
| 演示身份固定为三个 | 超级管理员、平台运营、只读审计覆盖「绕过 / 部分写 / 纯读」三种典型边界 |
| 无权限页默认切换为只读审计 | 避免出现「超级管理员被 403」的语义矛盾 |
| 权限目录采用分组长表而非分页 | 权限码是契约清单，分组浏览比翻页更利于核对；搜索与范围筛选承担定位 |

### 12.2 未覆盖内容

- 业务模块（Agent / 模型 / 知识库 / 工具等）的完整页面与按钮：本原型只保留导航入口，授权控件映射已在 PRD 中定义。
- 真实数据、接口调用、错误码处理与登录态：属于实现阶段。
- 移动端的完整交互：仅保证布局不破版，未设计移动端专属操作模式。

### 12.3 后续可扩展

- 角色对比模式：任选两个角色并排查看差异。
- 权限变更影响预览：修改角色权限前，显示受影响的用户与页面。
- 数据范围（行级）授权：在矩阵中增加「全部 / 本人 / 指定部门」列。
