# 辰光 Agent 平台 — 项目启动注意事项

> 适用代码：`chenguang-agent-platform-v4`
> 文档版本：2026-10-25
> 实测环境：Windows 11（10.0.26200）+ Python 3.14.8 + Node.js 24.22.0

---

## 1. 本地运行模式说明

本项目已改造为**免 Docker 的本地开发模式**，不依赖 MySQL、Redis、MinIO 三个外部服务：

| 组件 | 本地开发实现 | 说明 |
|------|--------------|------|
| 数据库 | SQLite（`chenguang.db`） | 由 `src/core/config.py` 的 `DATABASE_URL` 固定为 `sqlite+aiosqlite:///./chenguang.db` |
| 缓存 | fakeredis（进程内内存） | `src/infra/redis_cache.py`，验证码、登录态等重启即失效 |
| 对象存储 | `MockMinioClient`（进程内内存） | `src/infra/mock_minio.py`，由 `USE_MOCK_MINIO=true` 开启，已上传文档重启即丢失 |

因此本地启动**不需要**执行 `docker compose up`，也不需要本机安装 MySQL/Redis/MinIO。

> 若后续要切回真实服务（MySQL/Redis/MinIO），请先阅读第 10 节，涉及依赖与配置的额外改动。

## 3. 快速启动

### 3.1 一键启动（推荐）

双击项目根目录的 **`start.bat`**。

脚本会自动完成 5 个步骤：

1. 检查 Python 并校验虚拟环境（.venv 失效时自动重建）
2. 检查并安装后端依赖
3. 初始化 / 升级 SQLite 数据库并写入演示数据
4. 检查并安装前端依赖
5. 启动后端（8080）与前端（5173），等待就绪后打开浏览器

服务已在运行时重复执行是安全的：脚本检测到端口被占用会跳过对应启动。

### 3.2 手动启动

后端（项目根目录）：

```bat
.venv\Scripts\python.exe -m uvicorn src.main:app --host 127.0.0.1 --port 8080
```

前端（`app` 目录，本机执行策略禁用了 `npm.ps1`，**必须用 `npm.cmd`**）：

```bat
npm.cmd run dev
```

### 3.3 访问地址

| 用途 | 地址 |
|------|------|
| 前端界面 | http://localhost:5173 |
| 后端健康检查 | http://localhost:8080/health |
| Swagger API 文档 | http://localhost:8080/docs |
| 默认账号 | `admin` / `123456` |

> 登录需要输入图形验证码；验证码保存在 fakeredis 内存中，有效期为 5 分钟，**后端重启后旧验证码立即失效**，刷新页面重新获取即可。

## 4. 本次启动所做修复（重要）

本次在本机启动时遇到 4 个问题，已修复。重新拷贝项目或换机器时请留意。

### 4.1 虚拟环境 `.venv` 不可用（启动失败根因）

现象：`.venv\Scripts\python.exe` 文件存在，但一执行就报错：

```
did not find executable at 'C:\Users\admin\AppData\Local\Programs\Python\Python313\python.exe'
```

原因：仓库里携带的 `.venv` 是在**另一台电脑**（用户 `admin`、Python 3.13）上创建的，其 `pyvenv.cfg` 指向的解释器在本机不存在。虚拟环境**不可跨机器拷贝**。

修复：

- 已用本机 Python 3.14.8 重建 `.venv` 并重新安装依赖；
- `start.bat` 不再只看 `python.exe` 是否存在，而是执行 `"%PY%" -c "import sys"` 做可用性校验，失效时自动删除并重建 `.venv`。

> 今后拉取代码或拷贝项目时，**不要拷贝 `.venv` 目录**（已在 `.gitignore` 中排除）。

### 4.2 `requirements.txt` 依赖问题

| 问题 | 修复 |
|------|------|
| `asyncmy==0.2.11`（MySQL 异步驱动）在 Python 3.14 下没有可用的预编译 wheel，`pip install` 直接失败 | 已从 `requirements.txt` 移除。当前使用 SQLite，不需要 MySQL 驱动 |
| `src/infra/minio_client.py` 中 `from minio import Minio`，但 `requirements.txt` 缺少 `minio` 包 | 已补充 `minio==7.2.20` |

### 4.3 MinIO 在本地无法工作

现象：本机未运行 MinIO（9000 端口空闲），启动日志报“minio 桶创建失败”，知识库上传文档会失败。

修复：

- `MockMinioClient` 已接入 `src/infra/minio_client.py`，通过配置项 `USE_MOCK_MINIO` 切换；
- 本地 `.env` 已设置 `USE_MOCK_MINIO=true`；
- `.env.example` 同步新增该配置项（默认 `false`）；
- `download_file()` 兼容内存实现返回的 `BytesIO`（无 `release_conn` 方法）。

### 4.4 `start.bat` 的重写内容

| 改动 | 目的 |
|------|------|
| 新增虚拟环境可用性检测 + 自动重建 | 根治 `.venv` 跨机拷贝导致启动失败 |
| 新增 Python 版本检查（≥ 3.10） | 提前给出明确错误，而不是依赖安装后才报错 |
| 依赖自检加入 `minio` | 与 `requirements.txt` 保持一致 |
| pip 安装改为“清华镜像 → 官方源”两级回退 | 提高国内网络下的安装成功率 |
| 新增 `npm.cmd` 存在性检查 | 避免缺少 Node.js 时给出费解的报错 |
| npm 安装结果先存变量再 `popd` | 避免 `popd` 覆盖 `ERRORLEVEL` 导致误判 |
| 中文提示文案与编码保持 GBK + CRLF | 兼容 CMD 传统代码页，不出现乱码 |

> **编码要求**：`start.bat` 必须保存为 **GBK 编码 + CRLF 换行**。CMD 在 `chcp 65001` 下读取 UTF-8 批处理可能出现文件指针错乱，纯 LF 换行会拆断 `if`/`for` 复合语句。修改时请保持这一约定（仓库内已按此格式保存）。

## 5. 启动流程与文件说明

| 文件 | 作用 |
|------|------|
| `start.bat` | 一键启动入口（5 步流程） |
| `bootstrap_db.py` | 数据库引导：缺库则建表+灌数据、缺迁移版本表则标记、落后则 `alembic upgrade head`、迁移失败则备份后重建 |
| `init_data.py` | 建表并写入演示数据（用户/角色/权限、供应商/模型、Prompt、知识库、工具、Agent），可重复执行 |
| `wait_ready.py` | 轮询 `/health` 与前端 5173，等待服务就绪 |
| `chenguang.db` | SQLite 数据库文件（**不应提交到 Git**） |
| `logs/` | 运行日志目录（**不应提交到 Git**） |
| `alembic/versions/` | 数据库迁移脚本 |

前端配置：

- `app/.env.local` 控制前端数据来源：
  ```ini
  VITE_USE_MOCK=false
  VITE_API_BASE=http://localhost:8080/api/v1
  ```
- `VITE_USE_MOCK=false` 时走真实后端；未设置或为其他值时默认走 `app/src/services/mock/` 的模拟数据。
- 新建环境若缺少 `app/.env.local`，前端会默认使用 **mock 数据**，表现为“页面有数据但后端没收到请求”。

后端配置：

- `.env` 由 `pydantic_settings` 加载，并使用 `lru_cache` 单例缓存，**修改 `.env` 后必须重启后端**才生效。

## 7. 常见问题（FAQ）

### Q1：双击 `start.bat` 一闪而过
在 CMD 窗口中执行 `start.bat` 查看完整报错；或确认文件编码仍为 GBK + CRLF。脚本在所有错误分支都保留了 `pause`，正常双击不会一闪而过。

### Q2：提示 `did not find executable at ...Python313\python.exe`
本机 `.venv` 是跨机器拷贝的坏环境。删除 `.venv` 目录后重新双击 `start.bat`（新版脚本会自动重建）。手工删除：

```bat
rmdir /s /q .venv
```

### Q3：`pip install` 很慢或失败
脚本已默认使用清华镜像并回退官方源。也可手动设置：

```bat
.venv\Scripts\python.exe -m pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

### Q4：`npm run dev` 报“禁止运行脚本 / npm.ps1 无法加载”
本机 PowerShell 执行策略限制了 `npm.ps1`，请使用 `npm.cmd`（`start.bat` 已使用 npm.cmd）。

### Q5：端口被占用（8080 / 5173）
查看占用进程：

```bat
netstat -ano | findstr :8080
taskkill /F /PID <PID>
```

`start.bat` 检测到端口占用时会跳过对应服务启动，不会报错退出。

### Q6：数据库损坏或迁移失败
`bootstrap_db.py` 会先把旧库备份为 `chenguang.db.bak_<时间戳>`，然后重建并灌入演示数据。需要彻底重置时：

```bat
del chenguang.db
.venv\Scripts\python.exe bootstrap_db.py
```

### Q7：登录后立刻跳回登录页 / 提示 Unauthorized
JWT 有效期为 30 分钟，过期后前端会自动跳转登录页。另外**后端重启不会导致 token 失效**（JWT 无服务端会话），但验证码会失效。

### Q8：知识库上传的文档重启后不见了
本地使用内存版 MinIO（`USE_MOCK_MINIO=true`），文件只存在于后端进程内存中。需要持久化时请启动真实 MinIO 并设置 `USE_MOCK_MINIO=false`。

### Q9：前端页面有数据，但后端日志没有请求
说明前端走了 mock 数据。检查 `app/.env.local` 是否存在且包含 `VITE_USE_MOCK=false`，修改后需重启 Vite（`start.bat` 会重启）。

### Q10：中文日志乱码
`start.bat` 设置了 `chcp 936` 与 `PYTHONIOENCODING=gbk`。若在 VSCode/PowerShell 中查看日志出现乱码，属于终端代码页差异，不影响运行；`logs/` 下的日志文件本身为 UTF-8。

## 8. 停止与重置

- **停止服务**：关闭 `start.bat` 启动的两个命令行窗口（标题分别为“辰光Agent-后端 8080”“辰光Agent-前端 5173”）即可。
- **重置数据库**：删除 `chenguang.db` 后重新运行 `start.bat`。
- **重置依赖**：删除 `.venv` 与 `app/node_modules` 后重新运行 `start.bat`（耗时较长）。

## 9. 生产环境部署注意事项

本地免 Docker 模式**仅用于开发**，上线前至少需要处理：

1. **数据库**：`src/core/config.py` 中 `DATABASE_URL` 目前硬编码为 SQLite，需改为从环境变量读取并切到 MySQL/PostgreSQL；MySQL 驱动在 Python 3.14 下建议使用 `aiomysql`（`asyncmy` 暂无 3.14 wheel）。
2. **缓存**：`src/infra/redis_cache.py` 需换回真实 Redis，否则多进程部署时验证码/登录态互不可见。
3. **对象存储**：设置 `USE_MOCK_MINIO=false` 并部署 MinIO，注意桶的持久化与访问策略。
4. **密钥**：`src/utils/jwt_utils.py` 中 `SECRET_KEY` 为硬编码常量，生产环境必须改为从环境变量读取并定期轮换。
5. **默认账号**：首次初始化会创建 `admin/123456`，上线前必须修改密码。
6. **调试开关**：`.env` 中 `APP_DEBUG=true` 会打印全部 SQL，生产环境应设为 `false`。
7. **CORS**：`src/main.py` 仅允许 `http://localhost:3000` 与 `http://localhost:5173`，需按实际域名调整。
8. **敏感文件**：`.env`、`chenguang.db`、`logs/`、`.venv/`、`app/node_modules/` 均不应提交到 Git。
9. **前端构建**：生产环境使用 `cd app && npm.cmd run build` 产出 `app/dist/`，由 Nginx 等静态服务器托管，并将 `/api/v1` 反向代理到后端。
